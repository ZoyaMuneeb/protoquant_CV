Compare dense ProtoQuant (3,000 prototypes), P1-only (1,300) and batched loss-aware physical pruning (1,300). All use the same improved-backbone checkpoint and data split. Selection uses training data; assessment uses validation. There is no retraining or test-set evaluation.

1. Setup

Use after the new runner has been published to this branch. From your existing clone:

cd /home/shaikha/protoquant_CV
git fetch origin
git switch pilot/physical-lossaware
git pull --ff-only origin pilot/physical-lossaware
ls -l scripts/run_physical_target.sh

If the launcher is missing, stop and ask us to publish the update. Set the following paths in the same terminal; this resets the old pilot's checkpoint/cache settings:

export VENV=/home/shaikha/.venv
export BACKBONE_CKPT=/home/shaikha/runs/backbone_sweep/continue_lr_2e-4_lr_5e-5/ckpt/\
cub200_convnext_tiny_full_20261118_223411.pth
export BB2_RUNS_ROOT=/home/shaikha/runs_bb2
export PHASE1_ROOT="$BB2_RUNS_ROOT/phase1"
export CACHE_DIR="$PHASE1_ROOT/feature_cache"
export CUB_PATH=/home/shaikha/data/cub200_cropped
unset PQ_CKPT P1_REUSE_DIR DENSE_EVAL_PREFIX TARGET_OUTPUT_DIR
ls -lh "$VENV/bin/python" "$BACKBONE_CKPT" \
  "$PHASE1_ROOT"/strict_s40/stage2/pipnet_*.pth \
  "$CACHE_DIR/train.pt" "$CACHE_DIR/val.pt"
test -d "$CUB_PATH/CUB_200_2011/images" && echo "Dataset found"

Copy both lines of the continued backbone path. The listing must succeed and the last check must print Dataset found. The launcher discovers exactly one dense seed-40 checkpoint in runs_bb2/phase1/strict_s40/stage2. If there are several, set PQ_CKPT to the correct file's full path. Keep this improved backbone and its cache together.

2. Run

a) Smoke test first. Runs correctness tests plus a small real-input check: 200 training images, 32 validation images and two deletions. Pruned models end at 2,998.

bash scripts/run_physical_target.sh --smoke

b) Complete comparison. After smoke succeeds, run all three configurations; each pruned model ends at 1,300.

bash scripts/run_physical_target.sh --target-count 1300

Each command creates a fresh output folder automatically. Full-run runtime has not yet been measured; CUDA is required. Defaults: 400 training/calibration images, shortlist 64 and deletion batch 8. Optional synthetic-only check: bash scripts/run_physical_target.sh --self-test.

3. Check

The launcher prints [TARGET] output=.... Default folders are under /home/shaikha/runs_bb2/physical_target_1300_*. In another terminal, select the newest folder, confirm it matches the printed path, and watch progress:

export TARGET_OUTPUT_DIR="$(ls -dt \
  /home/shaikha/runs_bb2/physical_target_1300_* | head -n 1)"
tail -f "$TARGET_OUTPUT_DIR/run.log"

When finished, open results.md. Success means a final [DONE] message, a DONE file and state.json showing completed.

Send back: root results.md, results.csv, results.json, config.json, calibration.json, cache_feature_checks.json, starting_checks.json and run.log; also p1/results.json, batched/results.json and batched/decisions.jsonl. Keep checkpoints on the GPU machine.

4. If something breaks

  • Missing or ambiguous checkpoint / missing dataset. Repeat section 1. Set PQ_CKPT explicitly if discovery finds several files. Use the improved-backbone dense seed-40 checkpoint with 3,000 prototypes.
  • Cache warning or mismatch. An accepted bounded numerical cache drift warning is allowed. For a failed check, send cache diagnostics and run.log; verify the matched inputs first. If caches are missing or rebuilding is agreed, use a fresh folder:
export CACHE_DIR="$PHASE1_ROOT/cache_pilot_$(date +%Y%m%d_%H%M%S)"
PQ_CUB_PROTOCOL=strict "$VENV/bin/python" scripts/cache_features.py \
  --backbone_ckpt "$BACKBONE_CKPT" --cub_path "$CUB_PATH" \
  --out_dir "$CACHE_DIR" --splits train val
  • GPU out of memory. Start a new run with smaller chunks (add --smoke if retrying smoke):
unset TARGET_OUTPUT_DIR
PILOT_IMAGE_BATCH=8 CANDIDATE_CHUNK_SIZE=1 \
  bash scripts/run_physical_target.sh --target-count 1300
  • Interrupted run or output already exists. There is no resume. Keep the old folder, run unset TARGET_OUTPUT_DIR in the execution terminal, and rerun the same smoke/full command. A fresh folder is created.
  • Existing dense report is incompatible. Verify the input bundle first. To skip this optional reference, set export DENSE_EVAL_PREFIX="", then start a new run; dense validation will still be measured.

Reporting errors: share state.json, config.json, cache diagnostics, the failing method's decisions.jsonl where present, and run.log. For an earlier failure, send terminal output.

tail -n 30 "$TARGET_OUTPUT_DIR/run.log"
