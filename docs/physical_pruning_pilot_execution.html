ProtoQuant: Loss-Aware Physical
Pruning Pilot — How to Run It

Nov 20, 2026  ·  Seed 40

Compare P1-only, greedy loss-aware, and batched loss-aware physical pruning from the same checkpoint. Pilot 1 removes 160 prototypes (3,000 → 2,840). Pilot 2 starts from one shared P1-pruned model, recalculates P1, and removes 160 more (1,700 → 1,540). Selection uses training data; assessment uses validation data. There is no retraining.

1. Setup

From the repository root, retrieve the published branch:

git fetch origin
git switch pilot/physical-lossaware
git pull --ff-only origin pilot/physical-lossaware
git branch --show-current

The last line should print pilot/physical-lossaware. Set the matching Phase 1 backbone, dense seed-40 checkpoint, and cache paths. Replace these examples with your own paths:

export BACKBONE_CKPT="/path/to/backbone.pth"
export PQ_CKPT="/path/to/strict_s40/stage2/pipnet_checkpoint.pth"
export CACHE_DIR="/path/to/phase1/feature_cache"
export CUB_PATH="/path/to/cub200_cropped"
ls -lh "$BACKBONE_CKPT" "$PQ_CKPT" \
  "$CACHE_DIR/train.pt" "$CACHE_DIR/val.pt"
test -d "$CUB_PATH/CUB_200_2011/images"

The file listing must succeed; the directory check exits silently on success. Use the existing environment at ../.venv, or set export VENV="/path/to/.venv". CUB_PATH contains CUB_200_2011. The launcher checks the strict split and matching inputs.

2. Run

a) Smoke test. Run this first. It checks correctness and both pilots using 200 training images, 32 validation images, and only two removals per method.

export PILOT_OUTPUT_DIR="$PWD/../runs/pilot_smoke_$(date +%Y%m%d_%H%M%S)"
bash scripts/run_physical_pilot.sh --smoke

b) Complete pilot. After the smoke test passes, run all six method/pilot combinations at the full 160-removal budget.

export PILOT_OUTPUT_DIR="$PWD/../runs/physical_pilot_$(date +%Y%m%d_%H%M%S)"
bash scripts/run_physical_pilot.sh

Full-pilot runtime has not yet been measured. The full run requires CUDA. Default shortlist is 64 candidates; the batched method proposes up to eight deletions at a time.

3. Check

All outputs go to $PILOT_OUTPUT_DIR, printed at startup. In another terminal, set that variable to the printed folder and check progress:

export PILOT_OUTPUT_DIR="/path/printed/by/the/launcher"
tail -f "$PILOT_OUTPUT_DIR/run.log"

When the run finishes, open results.md in that folder.

CheckWhat you should see after the complete pilot
CompletionA final [DONE] message, a DONE file, and state.json showing completed.
SummarySix rows in results.md, results.csv, and results.json: three methods for each pilot.
Physical countsPilot 1 ends at 2,840; Pilot 2 ends at 1,540, for every method. Smoke runs instead end at 2,998 and 1,698.
Checks and measuresInference and reload checks pass. Results record validation accuracy/loss, calibration loss, pruning seconds, GPU memory, and edge counts.
Method outputsEach pilot*/p1, greedy, and batched folder has pruned.pth, results.json, and decisions.jsonl. Batch fallbacks include reasons.

Send back the root results.md, results.csv, results.json, config.json, calibration.json, and run.log, plus both batched/decisions.jsonl files. Keep the checkpoints on the GPU machine and share their paths.

4. If something breaks

  • Missing checkpoint or dataset. Correct BACKBONE_CKPT, PQ_CKPT, or CUB_PATH and repeat the checks in section 1. Use the dense 3,000-prototype seed-40 model.
  • Missing or mismatched cache. Use the matching backbone and create training/validation caches below. For stale hashes, IDs, or features, rebuild into a fresh CACHE_DIR.
VENV="${VENV:-../.venv}"
PQ_CUB_PROTOCOL=strict "$VENV/bin/python" scripts/cache_features.py \
  --backbone_ckpt "$BACKBONE_CKPT" --cub_path "$CUB_PATH" \
  --out_dir "$CACHE_DIR" --splits train val
  • Interrupted run or “output already exists”. This pilot cannot resume. Keep the old folder, set a new timestamped PILOT_OUTPUT_DIR (section 2), and restart the whole command.
  • GPU out of memory. Use a new output folder and smaller computation chunks:
PILOT_IMAGE_BATCH=8 CANDIDATE_CHUNK_SIZE=1 \
  bash scripts/run_physical_pilot.sh

Any other error, including a failed inference check: send state.json, config.json if present, the failing method’s decisions.jsonl, and the last 30 log lines. For an earlier failure, send the terminal message.

tail -n 30 "$PILOT_OUTPUT_DIR/run.log"
